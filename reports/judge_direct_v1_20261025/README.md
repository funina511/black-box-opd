# direct_v1 Judge 实验（2026-10-25）

2026-10-26后续真实训练已完成，见[Warmup→GAD与保存恢复报告](../judge_direct_training_20261026/README.md)。本页保留10月25日固定样本实验的状态、预算和结论。

状态：**候选实现、CPU回归、固定32条并发2/8对照、一次8条澄清复查均已完成。质量尚未放行正式joint。** 真实训练探针由用户明确留待后续；未启动正式训练或新的完整测评。

本轮总共72次Judge生成发送，未超过80次/2小时预算。服务已停止，6/7卡释放；190个受保护文件hash全部一致，1–4卡评估保持运行。

## 先看结论

1. 单轮通路工作正常：每条只有一次生成，不再因缺少events/evidence或复核而Mask有效标签。
2. 相同32条输入，并发8整批耗时约403秒，对比并发2的827秒下降51.3%；两档均30/32可解析，无OOM。
3. 最终JSON中位约19tokens（本地重新分词估计）；成本仍主要是Thinking。两条相同长轨迹在两档都耗尽8192输出预算，不能用提高并发消除这类尾部。
4. 一次澄清改善错误参数化的严重度判断，但符号改写仍被算作实质进展、纯复述仍得到error=0、递推中的严重错误仍被低估。**暂不建议直接起正式joint；不再扩大prompt或自动换模型继续调试。**
5. Critic排序诊断没有给出清楚的排序正确率提升证据，详见另份报告；没有据此修改奖励通路。

## 固定范围

- 正式数据仍为 **dapo_math_17k_v2**，不采用 cnt，也不生成 API Teacher 数据。
- 仅使用 GPU **6、7，TP=2**。1–4 卡上正在运行的评估不停止、不修改。
- Qwen3-8B Thinking；输出预算8192、上下文32768、bfloat16。Judge服务维持原 eager 设置，不顺便测试 CUDA Graph。
- 单轮直接输出两个0/0.5/1/null 标签，无事件、证据字段或二次复核。correctness仍由本地统一 scorer 提供，Actor reward仍为adv。
- 每个全局逻辑 optimizer minibatch最多抽样16条唯一轨迹，BT/correctness保持全量，lambda=0.1、tau=4及固定三维分母保持不变。

## 本轮真实测试

冻结32条：24条原始17k训练轨迹（8 Teacher、16 Student）+8个简短数学边界样例；真实样本含截断回答，仅覆盖训练步骤1和272。没有把正式评测回答用作Judge调参样本。

同一份输入先后以并发2、8请求同一服务，实际API共享对应并发上限。每条一次请求，没有自动复核或不变prompt重试。共享预算80次生成、2小时墙钟，每档至多1小时；超时提交记入消耗，不清零重跑。该放宽依据用户本轮“测试预算可以放宽”的授权。

真实8条的抽查参考在读取组别结果前已记录于 `real8_reference.json`；包含完整可见内容、两个截断学生回答和明确算术核查。它属于执行模型检查，不是人工准确率；所有`human_verified`保持false。

两条失败均为 `gad_student_13` 和 `gad_student_18`；未返回最终JSON，不能作为0分负标签。没有数学null输出，程序接纳率高不等于评分可靠。硬件物理占用见`fixed32/gpu_samples.jsonl`，不是PyTorch累计内存计数。

## 一次澄清后的8条复查

在不增加字段或调用链的前提下，澄清“换符号不算新结果”“独立进展不被后续错误抹掉”“错误参数化/递推污染属于严重错误”“无数学内容及无法核查内容的null语义”。只检查5条受影响样例和3条对照，总8次生成；45.9秒完成，8条均可解析。该选择性小样本不能用于与整批32条做速度比较。

| 样例 | 澄清后结果 | 判读 |
|---|---|---|
| 错误抛物线参数化的真实学生回答 | progress=0.5,error=1 | 严重度得到修正，独立的焦点/顶点结果保留 |
| 递推学生回答，把24336/144算成1728并污染后续 | progress=0.5,error=0.5 | 仍低估错误；实际商为169 |
| 对数题仅做符号替换再给错误答案 | progress=0.5,error=1 | 仍未满足“符号改写不算实质进展”的定义 |
| 纯复述 | progress=0,error=0 | 仍未遵守本轮无数学工作时error=null的约定 |
| 未提供定理的回答 | progress=0.5,error=0.5 | 与原参考有分歧；也存在论证缺口的解释，保留争议，不宣称是已独立证明的数学误标 |

3条对照（正确前缀、完整正确、正确最终答案但推理含错）均保持预期标签。原始参考不因结果而改写。以上为执行模型检查与简单算术核查，不是人工精度；没有标记human_verified=true。

Thinking日志明确显示模型自己做出了上述判断，例如把纯复述理解为“没有发现错误”，而不是程序把null改写为0。澄清后的其他4个残余参考分歧及完整输出见`analysis.json`和`clarification/`；此后未继续修prompt或追加请求。

## 训练信息与成本解释

`analysis.json`包含每维 × 实际`correctness_label()`训练目标的交叉表、按角色和截断拆分的分布。历史raw `score.correct=None`在无最终答案时仍映射为训练correctness=0，不能直接拿该None当训练Mask；同时提供独立的评估映射交叉表。

初始并发2的真实轨迹中progress=1有9条，其中6条correctness=1；并发8为7条，其中6条correctness=1。过程分数没有完全重复正确性，但新增信息是否可靠仍需核查，不能仅以“不同于correctness”证明有价值。

当前代码在rollout之后、Critic更新之前同步等待标注，**不与同一步rollout重叠**。未执行训练探针，因此无法确认“每步额外耗时≤训练耗时50%”目标，也不能将含8个短边界的32条整批墙钟简单除2，当成实际16轨迹训练步成本。后续真实探针还需看冷缓存、Teacher命中和尾部等待。

## 比较限制

旧baseline/correctness训练时使用scorer `2a2b8a02…`，本候选按已合并修复的scorer `f3549b87…`生成新标签。原始17k数据相同并不能消除训练scorer变化；正式因果比较需匹配scorer，或明确保留该混杂，由用户安排对照实验。

Critic排序诊断见 `../critic_ranking_20261025/README.md`。结果暂未提供清楚的排序正确率提升证据；没有据此擅自改变奖励通路。Warmup12步→GAD新增4步及保存恢复尚未执行，待用户后续安排。
