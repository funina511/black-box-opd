## 哈希、断言与恢复校验

**确有可以删减的防御性代码。** 成本和后果取决于检查的对象是否改变，以及它在什么操作前执行。删除旧断点、发布得分和复用标签之前，应先检查这些动作依赖哪份证据。

### 会影响标签、断点或评分记录的检查

1. **标签缓存命中会把新摘要覆盖到旧摘要上。** `LabelCache.get` 先读 JSON 校验键，再打开文件算 SHA256，并直接写回 `references[key]`。在临时目录写入已登记的合法进度标签 0，再只把内容改成合法值 1，调用训练用的 `build_labels` 得到一次缓存命中、零个 Judge 请求。随后生成的快照也接受了 1。建议对一次读取的相同字节做解析和哈希。已有预期摘要时比较，首次见到时登记。验收应覆盖正常命中、同键合法值被改、以及恢复时 live 与 snapshot 冲突。此复现面向 naive，base-GAD 没有使用 Judge 标签。[缓存读取与快照](../../gad/extensions/label_cache.py#L13) · [标注命中路径](../../gad/extensions/annotation_work.py#L32)
2. **自动删除旧 checkpoint 的门槛低于同阶段恢复的实际要求。** 普通 SeqKD 临时副本里，最新步缺 Actor 的 `extra_state`，或优化器文件为零字节，保留规划仍可能列出上一份完整点供删除。同阶段 FSDP 要读取优化器、scheduler 和 RNG。正式 naive 的保留数为 1。带完整扩展清单的 rubric 断点另有逐角色、逐 rank 的非空检查。建议让删除决策和同阶段恢复共用“按本阶段实际角色可恢复”的判据。验收用坏的新点加好的旧点运行只读规划，删除名单应为空。首次跨阶段初始化和 HF 导出可继续只验证各自需要的输入。[保留规划](../../gad/tools/prune_checkpoints.py#L47) · [普通检查](../../gad/tools/prepare_gad_checkpoint.py#L104) · [扩展检查](../../gad/extensions/checkpoint_state.py#L21) · [原复现](../20261105/H200基线复盘与naive实验待办_20261118.md#sec8)

3. **外评 raw 在评分前后各算一次 SHA256，却没有比较两个值。** 用一道 gold=2 的临时题，经真实评分器把 `Answer: 2` 判对，在子进程返回后、父进程发布结果前将 raw 替换为 `Answer: 7`。得到的状态是 `complete`，摘要属于 7，落盘得分属于 2。这是并发替换复现。没有证据表明正式 baseline 发生过该情况。建议由评分器记录实际消费字节的摘要并绑定结果，或比较前后摘要，遇变化放弃发布。验收可在同一个交接点换文件，并确认系统不会复用错配结果。[评分前记录](../../evaluate/evaluate.py#L600) · [完成状态](../../evaluate/evaluate.py#L608)

## 训练与 Judge

**实验口径。** Base 是初始 Qwen3-0.6B。SeqKD 独立训练。base-GAD 从其自身的单头 Warmup 271 继续做 271 次 GAD 更新，终点 542。naive 从同一学生和共同 adv 初始化派生的四头 Critic 出发，独立做 rubric Warmup 和 GAD，Actor 仍只读 adv。后续 Actor-rubric 从这份 naive 的 Warmup 271 出发。三处采样数分别是已有 Teacher 池每题 1 条、GAD 每题 4 条、正式八任务外评每题 4 条。单头基线和四头 naive 的 Critic microbatch 分别为 4 和 2，共同 BT 项还存在 BF16 和 FP32 的差异。[baseline 配方](../../configs/h200_baseline_n4.yaml) · [naive 配方](../../configs/h200_naive_n4.yaml) · [Actor 配方](../../configs/h200_actor_n4.yaml)

### 排序是否超出了长度信号

从正式 GAD 的 69,376 条 rollout 按同一步、同一 UID 分组，只取 scorer 能确定的一正一错配对。每对各比较一次，严格排对才算胜出，并列计入分母。[逐条训练监控](/tmp/bloxopd_h200_runs/h200_baseline_06b_17k_n4/gad/extension_metrics.jsonl)

| 同题正误对 | 对数 | adv 选对 | 总选较短回答选对 |
|---|---:|---:|---:|
| 全部 | 15,086 | 10,186（67.52%） | 10,685（70.83%） |
| 两条均自然结束 | 8,003 | 4,567（57.07%） | 3,801（47.49%） |
| 两条均自然结束，短答 token 数至少为长答的 90% | 1,094 | 642（58.68%） | 543（49.63%） |

混入截断回答时，长度规则在总体上超过 adv。当两条都写完且长度相近时，adv 仍有识别正答的信号。训练中有 39,034 条撞到 8k 上限。在学生自然结束且判对的 9,293 个 Teacher/Student 配对中，原 scorer 判 Teacher 明确错的有 172 次，其中双方写完的有 165 次。BT 在这些例子上仍要求 Teacher 得分更高，这正是检验正确性辅助头的理由。这些数均为配对出现次数，同题可能出现多次。[BT 损失](../../gad/extensions/worker.py#L115) · [配对重建与标签口径](../20261105/H200基线复盘与naive实验待办_20261118.md#sec8)

### naive 与后续 Actor 的三个检查点

- **Judge 实际输入含两层聊天模板。** 学生已渲染的题面以 `skip_special_tokens=False` 解码，整段放入 Judge 的 `problem`，随后再套 Judge 模板。取正式训练首题，用本机 0.6B tokenizer 重现，当前请求得到 5 个 `im_start`、3 个 `im_end` 和一对空 thinking 标签。改传用户题面正文时为 3 个、2 个且无该空段。在真实 8B 上，用相同回答成对测两种输入，保留学生实际可见的题目范围。若采用修订版，更新输入协议和缓存身份。0.6B 的复现只证实输入差异，8B 的标签变化待测。[题面解码](../../gad/extensions/critic_batch.py#L21) · [direct 消息](../../rubric/core/process_direct.py#L39) · [客户端模板](../../gad/extensions/judge_client.py#L171)
- **逐角色、逐维报告入选且可标注回答的覆盖率。** 过程配额 32 由 Teacher 和 Student 共用。模拟 Judge 连续四步只回进度、严重度全为 `null`，空监督计数仍为零，严重度的直接损失权重也为零。建议对首批真实标签分别给出 p/e 的有效数、分母和严重错误样例。合法的 `null` 应保留。[覆盖计数与告警](../../gad/extensions/online_v2.py#L51) · [历史 Judge 抽查](../../reports/judge_direct_training_20261026/README.md#L88)
- **选参复核按题面分组，并验证影子日志覆盖。** 按 baseline 实际的 16,844 个 question ID 重建现有哈希分半，仅统一正文空白就发现 97 组题面变体跨两半。可以保留原 token 身份来对齐轨迹，另用规范化正文划分选择集和复核集，在看到 naive 结果前冻结。读取时按配方核对 272–542 步每步 64 个 UID、每组 4 行、共 69,376 行。现行读取器可让每步只剩一题的 1,084 行通过覆盖检查。审阅截断约束时也应按正确、错误、未决拆分。本机 23,666 个“截断对正常结束错答”的配对中，64 对的截断回答已判对，151 对未决。[按题选参](../../gad/tools/select_actor_reward.py#L25) · [截断分类与约束](../../gad/extensions/actor_reward.py#L274)

**会改变梯度的两项设计留给共同对照。** 现有 Actor 先在各微批取 token 均值，再按回答数累积，重新分桶可能改变损失。先决定每 token 等权或每回答等权，再验证相同逻辑 batch 重分桶后的损失与梯度。Teacher 的 2,492 条源截断回答中另有 251 条重编码后不足 8,192 tokens，原文没有 EOS，当前右填充却可能将补上的首个 EOS 纳入有效监督。可保留前缀，按真实长度和来源结束原因决定 EOS 与 Critic 的最后有效位置。[损失与分桶实例](../../reports/h200_deployment/baseline_throughput_notes.md#L51) · [Teacher EOS 复现](../20261105/H200基线复盘与naive实验待办_20261118.md#L51)

**配方中的温度和 seed 也值得显式记录。** 当前 SeqKD 与 vanilla Warmup 的 Teacher SFT 会用 rollout 温度 0.8 缩放 Teacher 路径的学生 logits。若研究学生探索温度，可先单独命名并固定监督温度，避免两个量一起变化。SeqKD 的数据采样器在本轮实际使用默认 seed 1，Warmup、GAD 的数据 seed 为 42。按实际 Actor 更新次数计，SeqKD 有 533 次，Warmup 262 次加 GAD 271 次同为 533 次。[SeqKD SFT](../../gad/.backends_gad_extensions_v1_f0ce22a97d40/seqkd/verl/workers/actor/dp_actor.py#L518) · [Warmup 温度传递](../../gad/tools/algorithm_patches.py#L48) · [data.seed 转发](../../gad/tools/pipeline.py#L427) · [SeqKD 采样器](../../gad/.backends_gad_extensions_v1_f0ce22a97d40/seqkd/verl/trainer/main_ppo.py#L254)
