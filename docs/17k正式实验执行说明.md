# 17k 新版运行与迁移

适用于本轮新增运行。历史 `baseline_06b_17k`、旧数据和 `6d392bc15097` backend 保持原样。
实施结果、实际 GPU 验证及限制以 [附录 B/C/D 交付报告](../reports/formal17k_bcd_20261020/README.md) 为准；历史四卡交接证据保留在前轮报告中。报告在迁移包外单独交付。

## 配置与正式启动

```bash
cd /path/to/LMOps
export GAD_PYTHON=/path/to/gad/env/bin/python

# 只检查，不训练。correctness_only / rubric_joint 可替换 baseline。
bash scripts/preflight.sh --model qwen3_0.6b --dataset dapo_math_17k_v2 \
  --method baseline --machine 3090_4gpu --stages seqkd,warmup,gad --prepare-backends
bash scripts/train.sh --model qwen3_0.6b --dataset dapo_math_17k_v2 \
  --method baseline --machine 3090_4gpu --run-id baseline_06b_17k_vnext \
  --stages seqkd,warmup,gad --dry-run

# 正式运行由用户启动：移除 --dry-run；三种方法使用不同 run-id。
```

首次安装或代码版本变更时，`--prepare-backends` 会先重建对应固定源码的隔离工作树，不启动训练。
普通训练入口本身会先准备 backend 再预检；只运行 dry-run 不会创建 backend。

`--method baseline|correctness_only|rubric_joint` 读取 `configs/methods/`；
`--machine 3090_4gpu` 或机器 YAML 路径读取机器设置。覆盖顺序是：
全局/模型/数据选择 → 方法 → 机器 → 显式 `--overrides` → `--set`。
机器层用于路径/资源/性能，不应覆盖方法的数学定义。最终只保存一份 `runs/<run-id>/train.yaml`。
恢复时不重新读取方法文件，也不能把 `--method/--machine` 与 `--run` 混用。

这三份方法配置明确：seed42、batch64、non-thinking Actor、2048/8192、SeqKD2epoch、
Warmup1epoch、GAD累计2epoch（271→542，新增271）。SeqKD独立，Warmup从base开始，GAD接Warmup。
共同单头adv初始化为 `assets/initialization/qwen3_0.6b_math_v2_adv_seed42`；扩头保留adv权重。
correctness/joint使用fixed_dimension_gated、λ=.1、τ=4、固定三维分母；Replay关闭。
原SeqKD的前9步不更新Actor及其sampler seed1保持不变；其它训练随机源仍按原显式seed42。

Joint启动前先启动独立Judge（8B Thinking，GPU6/7）：

```bash
bash scripts/rubric_judge.sh --method rubric_joint --machine 3090_4gpu --action start
bash scripts/rubric_judge.sh --method rubric_joint --machine 3090_4gpu --action health
bash scripts/preflight.sh --model qwen3_0.6b --dataset dapo_math_17k_v2 \
  --method rubric_joint --machine 3090_4gpu --stages warmup,gad
# 训练使用相同方法与机器参数；correctness_only、baseline不需要Judge。
```

Judge并发2、Thinking、8192输出、一次定向复核、事件v2.7/input v2.5/review v4。
全步deadline明确设为14400秒（原短测1800），只是允许长批等待，不代表提速。
历史并发2时4条回答墙钟约277.7秒，即69.4秒/回答，已经包含并发收益。
GAD冷缓存上界64Teacher+128Student按相同吞吐粗估约3.70小时/step；
Teacher缓存命中后128Student约2.47小时，不能再次除以并发数。这是4条小样本线性外推，不是正式batch实测。
Thinking长度、复核和失败会改变成本，详见报告。

## 恢复、导出、评估

```bash
bash scripts/train.sh --run correctness_06b_17k_vnext --resume --stages warmup,gad
bash scripts/export_model.sh --run correctness_06b_17k_vnext --stage gad
# 其它阶段分别用 --stage seqkd 或 --stage warmup。
bash scripts/eval.sh --run correctness_06b_17k_vnext --methods base,seqkd,gad \
  --profile math_unified_v1_n8_math500n2_8k_vnext --dry-run
# 去掉 --dry-run 开始正式评估；只测GAD可写 --methods gad。
```

评估自动生成每个任务的 `expected_question_ids.json`，并以 `--expected-ids` 传入CPU评分器。
它采用固定OPRD sampler实际分配的ID；当前版本按行枚举，忽略Parquet的外部索引。
手工重评分非连续ID的既有raw时必须明确传ID文件，例如：

```bash
"$GAD_PYTHON" evaluate/rescore.py --raw-jsonl /path/raw_samples.jsonl \
  --expected-ids /path/expected_question_ids.json --n 2 --task MATH-500 \
  --output-dir /path/NEW_scores
```

相同评估重复运行会补齐未完成任务；新评分保留旧metrics并通过任务state指定当前版本。
真实修改模型、数据、seed、n或scorer必须换profile。完成状态、导出进度不是新的评估身份。

新GAD在启动前固定Warmup handoff内容身份；完成、跳过及恢复均校验。
旧GAD记录若缺来源身份，明确拒绝自动跳过/续训，旧文件不改；使用原冻结解释器或另行做显式来源核验。
仅HF导出不等于恢复checkpoint。扩展开启时必须包含 `training_extensions/` 和完整性marker。
首次Warmup→GAD不加载Warmup optimizer；同阶段恢复才加载完整worker状态，每角色一次。

## 角色开关与性能工具

`models.actor_param_offload` / `actor_optimizer_offload` 与 `critic_param_offload` /
`critic_optimizer_offload` 分开；未指定（null）时回退到旧 `models.param_offload/optimizer_offload`。
`models.actor_gradient_checkpointing` / `critic_gradient_checkpointing` 未指定时回退
`models.enable_gradient_checkpointing`。Reference仍单独使用 `models.ref_param_offload`；
新版FSDP1/2构造遵从此开关，Actor保留原手工offload路径。
本机配置先保留offload/checkpointing；候选是否推荐以实际显存与吞吐证据为准。

```bash
bash scripts/benchmark_train.sh --source-run runs/baseline_06b_17k \
  --source-step 500 --stage gad --candidate b0_control \
  --steps 4 --warmup-steps 1 --run-id my_control_probe
# 上面只组合配置；加 --execute 才复制checkpoint并实际短测。
```

工具只读源run、使用独立结果目录，保持原训练/scheduler目标，以工程调用步数结束并保存。
默认仅Warmup/GAD，同拓扑；不支持借短测做重分片。3秒采样的显存峰值可能漏瞬时尖峰。
4步包含1步预热、2步正常观测、1步保存退出；保存步不算正常观测。
这两个正常步不能支持稳定P90或整轮无OOM承诺。候选B1仅关闭eager，B2仅将Critic microbatch改为2；不叠加开关。

## 数据与Judge边界

`data/dapo_math_17k_gad_v2` 是只增元信息的派生版本；旧17k baseline无需因此自动重跑。
新manifest保留文件hash、Teacher采样fingerprint与派生Parquet指纹的区别，并记录来源截断统计。
仍为select=all，no_answer→correctness=0/valid=true，表示预算内没有可核验正确最终答案；
不能解释为过程一定有数学错误，progress/error独立判断。没有自动过滤或新增Mask。

事件至少一个证据区间，空事件`{}`拒绝；复核标签的额外空证据仍允许。
invalid unjudgeable同样阻断progress1/error0；error标签unknown本身不一刀切Mask独立full-progress。
数学unknown沿用连续空覆盖阈值，不再等同于全体结构失败立即停步。

Judge确认技术失败默认最多2次标注尝试（每次最多一次数学复核），journal保留累计记录。
未知远端提交状态默认不重发；本服务没有按请求查询任务状态的接口。
新run显式选择 `rubric.judge.unknown_submission_policy=retry` 才允许有限重试，可能重复远端计算。
合法数学unknown/低置信标签不作为技术故障重试；旧失败journal无尝试账本时明确拒绝自动迁移。

## 迁移

```bash
"$GAD_PYTHON" gad/tools/package_runtime.py \
  --config /path/to/resolved_train.yaml --output /path/to/NEW_runtime_package \
  --evidence-dir reports/formal17k_20261020
```

runtime.tar.gz包含运行源码、固定三阶段verl Git对象、OPRD采样依赖及许可证、
默认评估Parquet、源码/资产内容清单与实际环境版本；不包含训练数据和模型大资产。
加--include-assets同时生成assets.tar，携带所选方法的真实17k V2数据及模型资产；否则按manifest另行复制。
按包内REBUILD.md重建，填写 `configs/machines/server.example.yaml`，再预检/规划新run。
首版旁路内容hash不重写旧fingerprint；异路径旧run恢复和改变GPU拓扑未开放。
不能把锁定版本清单当作已备齐离线wheel或已验证任意驱动。

## 附录 B/C/D 发布目录

源码中包含 third_party/verl 的三提交具名 bundle（浅层提交边界由template/shallow明确携带）、固定OPRD sampler/grader、四份评估数据和environments记录。prepare缺源仓库时离线重建；已有非空平铺目录不会被覆盖。新实验不再依赖../OPRD、../model或历史runs初始化。历史配置/缓存仍不改路径。

```bash
# baseline/correctness_only资产相同；不要求Judge。
"$GAD_PYTHON" gad/tools/package_runtime.py --config /path/to/resolved_baseline.yaml \
  --output /path/to/NEW_release --include-assets
# runtime.tar.gz与assets.tar解包到同一父目录，只产生LMOps根目录。
```

只携带runtime时是源码/依赖包，须按manifest补齐模型和17k资产；完整资产包不包含Python/CUDA环境。旧run异路径续训及变拓扑恢复仍未开放。

普通CPU入口无需模型或历史报告；真实Qwen tokenizer/xgrammar兼容检查仅在显式设置GAD_TEST_QWEN_TOKENIZER时执行，未执行会报告skip。小型identity夹具不是可加载模型，不是Judge质量证据。
