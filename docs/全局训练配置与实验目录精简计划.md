# 全局训练配置与实验目录精简计划

计划日期：2026-10-07。2026-10-10 用户确认后实施；全局配置、通用入口及实验元数据归档已完成，GPU 新训练验证待后续实验。

0.6B / 17k 三阶段已完成后开始实施。下文保留批准的设计；当前使用方式见 [实验运行指南](实验运行指南.md)。旧实验 checkpoint 和结果目录保留原路径。

## 1. 推荐方案

维护一份 `LMOps/train.yaml` 作为新实验的默认配置。在通用 `scripts/train.sh` 顶部或启动参数中选择模型、数据集、实验备注和超参；正式启动时自动将完整配置写入对应 `runs/<运行名>/train.yaml`。

`experiments/` 不再是新实验启动的必需目录。每次运行仍保存独立的完整配置，用于恢复、导出、评测和复现，但由程序生成，无需用户手动复制维护。

配置和结果的关系为：

```text
全局 train.yaml + 模型/数据选择 + 本次参数
                    ↓
              校验并生成完整配置
                    ↓
        runs/<运行名>/train.yaml
                    ↓
          SeqKD → Warmup → GAD
                    ↓
       按同一 run 导出模型与评测
```

第一轮改造范围为配置解析、通用入口和实验元数据归档。沿用现有训练器、阶段关系、non-thinking 设置、数学评分口径及 checkpoint 保留规则。

## 2. 已核实的现状与依赖

| 位置 | 当前行为 | 改造方向 |
| --- | --- | --- |
| `scripts/train.sh` | 根据模型名和实验名拼接 `experiments/<名称>/train.yaml` | 选择全局默认配置，合成本次配置并自动归档 |
| `gad/tools/config.py` | 合并代码默认值与单份 YAML；路径相对 YAML 所在目录解析 | 集中实现模型/数据选择、覆盖合并、路径解析和 run 配置加载 |
| `gad/tools/pipeline.py` | 在 run 下保存实际配置快照，但仍以外部 YAML 为输入 | 新实验以自动生成的 run 配置为执行依据；恢复以该 run 配置为依据 |
| `evaluate/run_eval.sh`、`scripts/export_model.sh` | 都依赖 `experiments/` 查找训练配置 | 优先通过 `--run` 选择实验，与训练使用同一份配置 |
| `evaluate/evaluate.py` | 读取嵌套 YAML 推导目标步数，再核对 run 的扁平配置快照 | 通过统一解析函数加载配置，保留实际训练与评测对齐检查 |
| `scripts/preflight.sh` | 默认路径仍写死为 1.7B 实验 | 支持与训练相同的模型、数据集选择及已有 run |
| `scripts/sample.sh`、`gad/tools/benchmark_train.py` | 仍引用 1.7B 的采样配置和性能候选配置 | 更新共享配置位置及历史 run 选择方式，再整理旧目录 |

训练已经保存 `reports/resolved_configs/*.yaml` 和 `current_resolved_config.txt`，因此不需要另建一套配置记录系统。现有快照使用扁平的点号键；评测入口使用嵌套结构。这两种格式必须在统一加载时兼容。

已有 1.7B 实验的实际快照使用 `rollout.n=2`、GAD 绝对目标 2 epoch，而源 YAML 仍有其他预算；其 GAD 保存至 step 542 且没有完成标记。迁移应记录实际运行配置及各阶段产物，保留其探索性质，不能根据当前源 YAML 把它重新解释为完整对照实验。

## 3. 全局配置与启动参数

### 3.1 一份 YAML 包含公共设置和可选项

全局 `train.yaml` 包含两部分：公共训练设置，以及少量模型/数据集的名称映射。名称映射在解析后展开到现有训练字段，不传入训练器，不混入阶段训练签名。

- 模型映射：先支持 `qwen3_0.6b`、`qwen3_1.7b`，记录本地学生模型路径和判别器初始模型路径。判别器默认随学生切换，避免只改学生却沿用其他尺寸的判别器。
- 数据映射：先支持 `dapo_math_5k`、`dapo_math_17k`。每个映射绑定 train、dev、quick dev、manifest、teacher index 和教师指纹，整体切换。
- 公共设置：batch、学习率、生成长度、rollout、thinking、epoch 预算、GPU、验证及保存频率等。
- 首次默认值以当前 0.6B / 17k 探索配置为基准：non-thinking、GAD n=2、batch=64、SeqKD/Warmup/GAD 为 2/1/2 epoch。
- 切换模型或数据集只展开对应映射；预算、rollout 数等改动由公共设置或明确的覆盖参数控制，并在启动前打印。

不需要为每个模型、数据集组合添加完整 YAML。模型或数据真正新增时，在全局映射中登记一次。

### 3.2 覆盖顺序

```text
全局公共设置 → 所选模型/数据映射 → 可选的简短覆盖 YAML → 命令行 --set
```

用户可以只修改 `scripts/train.sh` 顶部的模型、数据集和 `OVERRIDES` 数组，也可以直接使用命令行。简短覆盖文件用于希望保存某组调参输入的场景，不是每次实验的必需文件。

全局配置中的相对路径以全局 YAML 所在目录为基准；覆盖文件中的路径先按该文件自身目录解析。合并后的运行配置使用绝对路径，防止保存到 `runs/` 后路径含义变化。

### 3.3 计划提供的命令形式

以下接口已实现：

```bash
# 打印计划：不启动训练，不创建 run、guard 或 checkpoint 文件
bash scripts/train.sh --model qwen3_0.6b --dataset dapo_math_17k \
  --name n2 --set rollout.n=2 --dry-run

# 正式启动：自动生成本次 runs/<运行名>/train.yaml
bash scripts/train.sh --model qwen3_0.6b --dataset dapo_math_17k \
  --name n2 --set rollout.n=2

# 同一流程切换模型和数据
bash scripts/train.sh --model qwen3_1.7b --dataset dapo_math_5k --name trial

# 恢复、评测和导出都明确指定已有 run
bash scripts/train.sh --run runs/<运行名> --resume
bash evaluate/run_eval.sh --run runs/<运行名>
bash scripts/export_model.sh --run runs/<运行名> --stage gad --step latest
```

`--name` 是可选备注。新实验默认生成 `<模型>_<数据>_<备注>_<时间>` 的运行名，检查目录唯一性并打印完整路径。重复执行同一组参数默认创建新实验；续跑必须显式指定已有 run。

现有 `--config /path/to/train.yaml` 继续兼容。旧的按 `experiments/` 选择实验的参数在过渡期保留；删除旧目录前完成兼容解析或提供明确的替代命令，不能把旧续跑命令静默解释成新实验。

## 4. 自动保存配置与恢复规则

1. 启动前在内存中合并设置，校验模型/数据路径、教师指纹、thinking、batch、预算和 rollout 参数，打印实际数据行数、各阶段目标步数及结果路径。
2. 基础校验通过后创建新 run，以原子写入方式保存嵌套结构的完整 `train.yaml`。它包含本次所有生效的训练字段及已解析路径，而非只记录与默认值的差异。
3. 保存启动命令、配置摘要/哈希及现有的后端、数据指纹等元数据；预检报告放入该 run 的 `reports/`。
4. 本次 pipeline 使用刚生成的配置。执行时只有这一份完整配置作为依据。
5. 已有 run 恢复、导出和评测直接读其保存配置，不重新套用修改后的全局默认值。允许的运行参数覆盖（如 GPU、解释器）需单独记录，不能静默覆盖原训练配置。
6. 恢复时核对已完成阶段签名，并沿用现有阶段恢复机制；已有 GAD checkpoint 时走 full-state resume，没有 GAD checkpoint 时走正常 Warmup 交接。更换模型、数据、学习率、rollout 或训练预算时创建新实验。
7. 新 run 的完整配置保存一次；后续启动记录命令和允许的运行参数差异，减少反复保存相同完整 YAML。历史快照与记录保留，用于旧实验兼容。

训练阶段关系继续保持：SeqKD 是独立基线，Warmup 从初始学生开始，GAD 接续 Warmup。`budget.stage_epochs.gad` 继续表示绝对目标；启动日志应同时显示 Warmup 交接步、GAD 新增步和最终步，降低误解。

## 5. 目录合并方案

新实验采用更直接的结构：

```text
LMOps/
├── train.yaml                         # 日常维护的全局训练配置
├── scripts/                           # 通用训练、预检、导出、采样入口
├── evaluate/                          # 通用评测入口与实现
├── runs/
│   └── <模型>_<数据>_<备注>_<时间>/
│       ├── train.yaml                 # 自动生成的本次完整配置
│       ├── run_summary.json           # 运行摘要，复用现有机制
│       ├── seqkd/
│       ├── warmup/
│       ├── gad/
│       ├── logs/
│       ├── reports/
│       ├── runtime/                   # Hydra、guard 等运行辅助文件
│       └── eval/
├── docs/                              # 通用使用说明、修改计划
├── data/                              # 多个实验复用的准备好数据
├── assets/                            # 模型和原始数据链接
├── sample/                            # 数据生产实现及共享采样配置
└── gad/                               # 训练实现、共享工具和后端
```

`experiments/` 中的内容按用途归档：

| 现有内容 | 目标位置 |
| --- | --- |
| 每个实验的 `train.yaml` | 对应已有 run 的 `train.yaml`，根据实际快照生成并校验 |
| 每个实验的 README | 通用命令合并到统一使用说明，特有实验说明归档至对应 run 的 `reports/` |
| `qwen3_1.7b/sample.yaml` | `sample/configs/sample.yaml`，继续作为共享的数据生产配置 |
| `perf/candidates.yaml` | `gad/configs/benchmark_candidates.yaml`，更新性能工具引用 |
| 性能实测说明和历史记录 | 对应 run 的 `reports/legacy_experiment/`；后续性能工具输出在 `reports/performance/` |

已有 `runs/gad_qwen3_*/<run_id>/` 目录保留原路径，新增入口支持直接选择这类旧 run。把配置归入已有 run 即可，不搬运 checkpoint 实体。交接、导出、完成标记和评测记录中保存的绝对路径因此仍然有效。

`runs/` 当前被 Git 忽略。合并后，全局配置和生成逻辑继续受版本管理，每次运行的配置随该 run 一起备份；移除旧配置前应核对归档完整性。

采样配置不塞进训练 YAML：它描述共享教师数据的生产过程，不随每个学生训练实验重复维护。评测数据集和生成参数继续在现有通用评测入口设置；训练模型、训练数据、non-thinking 和 checkpoint 选择从目标 run 读取。

## 6. Checkpoint 规则

继续使用 `resources.save_freq: 50`、`resources.keep_last_checkpoints: 5`：每 50 个 global step 及阶段末保存，每阶段保留最近 5 次完整保存，与 epoch 无关。

现有监控每 30 秒检查一次，交接、已导出模型和完成结果额外受保护；正在写入的保存不清理。配置整理不扩大清理范围，不因迁移而清理现有 0.6B checkpoint。

## 7. 实施阶段与正在运行的实验

### 阶段 A：确认后准备实现与 CPU 验收

在隔离工作副本实现全局配置解析和新入口，复用 `config.py`、`pipeline.py` 及现有评测/导出工具。当前训练后续阶段还可能启动新的 Python 进程读取工具，因此在当前 run 使用的代码路径中直接改公共工具，不能视为只影响下一次启动。

完成配置合并、路径解析、命名、dry-run 和恢复/评测选 run 的 CPU 检查。此阶段不执行 GPU 训练测试。

### 阶段 B：当前 run 结束后切换通用入口

当前 0.6B / 17k 训练结束、相关进程退出后，将已验收实现切换到正式目录。为已有 run 补齐完整配置；先保留 `experiments/` 的旧入口，验证新旧入口加载的实际训练参数和阶段签名一致。

同步调整训练、预检、评测、导出、手动 checkpoint 清理、采样与性能工具的配置定位。所有入口共享 run/config 解析规则，避免各脚本继续各自猜测实验目录。

### 阶段 C：验收后整理旧目录

核对实际快照、实验说明、采样配置、性能记录均已归档，扫描仍在使用的路径引用。核对当前实验结束后的恢复、导出和评测计划，确认能定位原 checkpoint。

完成核对后，删除 `experiments/` 中已迁出的重复配置和说明，更新根 README。旧 run 的 checkpoint、日志、manifest 和评测结果保留原位置。

## 8. 验收标准

- 选择 0.6B / 5k、0.6B / 17k、1.7B / 5k 时，无需手工创建完整 YAML；在共用默认预算下，5k/17k 自动计算为 78/271 步每 epoch。
- 与当前 0.6B / 17k 配置对照，新入口默认生成相同的模型、数据、non-thinking、优化器和预算设置：SeqKD 542、Warmup 271、GAD 271→542。
- 参数覆盖顺序可验证；切换数据时 manifest、teacher index、quick dev 绑定正确；非法组合在启动前报告错误。
- `--dry-run` 不启动 GPU 任务，也不创建 run 或 guard 文件。
- 新实验不覆盖已有 run；同一 run 恢复不会因全局默认值变化而改变训练参数。
- 训练、评测、导出和清理工具读取同一份运行配置；flat/nested 历史 YAML 均能正确加载。
- 已完成 0.6B / 5k 阶段仍可被正确识别并跳过；1.7B 的 GAD step 542 仍被识别为已有探索保存点，不伪造完成状态。
- 路径和配置层变更不改原训练身份；正在运行的 0.6B / 17k 原路径和进度保持有效。
- 使用临时小文件验证最近 5 次保存的轮换及受保护保存点；不通过真实实验目录执行删除测试。
- `experiments/` 整理后，现有入口没有悬空的配置引用；文档只需解释全局配置、新实验启动和按 run 恢复/评测/导出。
