## 2. 已有 baseline 给出的参照

### 正确性监督为什么值得继续试

原 GAD 的 BT 损失鼓励把 Teacher 排在 Student 前面。即使某个 Student 答对、Teacher 答错，BT 的方向仍然相同。本机 base-GAD 的 Critic 区分两种来源的步均准确率为 96.8%。换成同题的两个学生回答，观察结果如下。

| 训练中的学生对照 | adv 严格把正答排在前面的比例 |
|---|---:|
| 两条都正常结束，一对一错 | 4,567 / 8,003 = **57.1%** |
| 正答正常结束、错答截断 | 5,535 / 6,884 = **80.4%** |

共 69,376 条 rollout，39,034 条撞到 8k 上限，17,344 组中有 4,890 组四条全截断。上表按有明确标签的配对统计，并列未计为胜出。外部 16k 评测中，GAD 有 2,257/12,384 条回答截断，其中 36 条仍获确认正确。后续宜并列报告同题完整正误对的排序、正确与错误回答的组内优势差、结束率和预算内答对率。[训练记录目录](/tmp/bloxopd_h200_runs/h200_baseline_06b_17k_n4/gad) · [外评分项](../../reports/h200_evaluation_20261118/baseline_all8_n4_detail.csv)

本机 8k 贪心 dev 的 512 道题可以逐题对齐。SeqKD 和 GAD 都写完的 79 题，确认答对数从 42 到 41；只有 GAD 写完的 110 题，从 2 到 32；只有 SeqKD 写完的 16 题，从 7 到 0；两者都截断的 307 题都没有确认答对。两组各有一条判分未决。整体 51→73 的变化主要发生在交卷状态改变的题上，这给本机 naive 提供了一个具体的比较维度。[SeqKD 逐题 dev](/tmp/bloxopd_h200_runs/h200_baseline_06b_17k_n4/seqkd/validation_rows_full_542_90ea2ad049004639831be4853e5d8144.jsonl) · [GAD 逐题 dev](/tmp/bloxopd_h200_runs/h200_baseline_06b_17k_n4/gad/validation_rows_full_542_29e5e698a64c41b984fdfcdf293e71ab.jsonl)

**历史证据支持继续试正确性辅助监督，具体机制仍待验证。** 旧机 n=2 的八任务下界依次为 baseline 24.92%、correctness-only 25.77%、naive rubric 26.70%。这两种辅助方法都可能通过共享 Critic 主干改变 adv。旧机固定 540 个正误对上，baseline 和 correctness-only 的最终 Critic 排序正确率同为 59.17%，该诊断未包含 naive。另一次旧机 n=4 的影子分析中，主网格里只有直接混入预测正确性 c 的候选通过，选择集 204 次修正、51 次破坏，收益集中于包含截断的配对。本机可让 baseline 与 naive Critic 给**同一批**固定学生回答打分，同时看排序和优势差，再对照外评。baseline 与 naive 比较的是含 Warmup 的整套方法，两者 Critic microbatch 也分别为 4 和 2；naive 与 Actor-rubric 共享 Warmup，适合比较奖励接入方式。[历史结果与 540 对诊断](../Rubric两版设计与近两周实验汇报_20261105.md#L89) · [n=4 影子分析](../../reports/gad_n4_selection_migration_20261114/README.md#L25)

## 3. 数据和训练中应另立版本的问题

### 同题跨集合，以及同题不同标准答案

现有划分按完整 prompt 哈希把题分组，并在同一 UID 内检查题面和答案。去掉固定指令、归一空白后，训练集与 dev 有 **9/512** 个 dev 行正文相同；与外评至少重合 AMC23 **4/40**、MATH-500 **4/500**、Olympiad-Bench **1/675**。这是精确匹配的下界。比如 AMC23 的零基行号 17 与训练 UID `16d60e70-f320-4b7b-9d3e-1ebb8b299d9f` 同题。只排除上述 9 道外评题，现有成绩下界重算为 **Base 14.68%、SeqKD 23.18%、GAD 27.41%**。整体顺序保持，AMC23 单项对重合更敏感。[划分逻辑](../../sample/prepare_prompts.py#L134) · [训练数据](../../data/dapo_math_17k_gad_v2/gad_train.parquet)

即使要求完整题面一字不差，训练集也有 **6 组**同题给出互斥整数答案，dev 有一组标为 99 和 21。训练 UID `1f36792a-8d4e-45f3-a493-f06d0a3895be` 与 `f09110c9-c0cc-4f50-ba00-07e47208efbf` 的题面相同，答案分别为 25 和 15。相同学生回答可能因此收到相反监督。下一版先核对冲突标签，用标准化题面分组划分数据，同时保留同题不同解法。旧结果可同时展示全榜与排除已知重题的榜单；近似改写需要核题，特别留意只改一个运算符的变式。[冲突检查](../../sample/prepare_prompts.py#L150) · [开发集](../../data/dapo_math_17k_gad_v2/gad_dev.parquet)

### 源截断的 Teacher 前缀被补上了有效结束符

按当前 scorer 复评，17,405 条训练 Teacher 回答中确认答对 13,656 条。2,492 条源截断回答里有 2,409 条没有明确答案，28 条已判对。用本机 0.6B tokenizer 重编码，源截断中有 **251 条**少于 8,192 tokens，且原文无结束符 EOS；另有 2,233 条恰好达到上限，8 条超过上限。dataset 用 EOS 右填充，后端根据首个 EOS 重建 mask 并包含该位置。有一条原文正好停在空的 `Answer:` 后，学生因而学到“这里该结束”。建议保留前缀的监督，通过真实长度和来源结束原因决定 EOS 是否有效，Critic 在最后一个真实有效 token 上打分。251 条对总成绩的影响仍待受控比较。[实际 SeqKD 填充](../../gad/.backends_gad_extensions_v1_f0ce22a97d40/seqkd/verl/utils/dataset/rl_dataset.py#L297) · [有效位置计算](../../gad/.backends_gad_extensions_v1_f0ce22a97d40/seqkd/verl/workers/rollout/vllm_rollout/vllm_rollout_spmd.py#L401)

### 显存分批改变了 Actor 的损失权重

当前 Actor 先在每个 microbatch 内取有效 token 的损失均值，再按该 microbatch 的回答数合并梯度。两条回答若分别有 1 和 3 个 token，各 token 损失分别为 0 和 1，一起计算结果为 0.75，分开计算得到 0.5。不同策略生成的回答长度不同，即使都用 10,240 的分桶预算，训练权重也会受到分桶影响。下一版先决定是每个 token 等权，还是每条回答等权，再按对应的全批分母归一。验收用同一个逻辑 batch 重新分桶，比较两次的损失和梯度。[本机吞吐分析](../../reports/h200_deployment/baseline_throughput_notes.md#L51) · [部署后端的实际累积](../../gad/.backends_gad_extensions_v1_f0ce22a97d40/gad/verl/workers/actor/dp_actor.py#L507)

## 5. 新一轮代码审查：哪些判断值得改

### 先修有错误后果的分支

1. **Teacher 恢复可能覆盖非空索引。** `prepare_index` 将“读到的第一行是空白”按空文件处理，直接写新表头。在临时副本用“空行 + 正式表头 + 一条真实回答”调用该函数，文件从 3 行变为只剩表头。正式 Teacher 索引首行正常。改法是只初始化新文件或零字节文件；已有内容时跳过前导空行读取表头，遇到损坏则保留原件并指出行号。恢复入口还会分开扫描指纹冲突、同 UID 的 prompt 变化、已完成 UID；可在一次遍历中同时获取这些信息和实际候选数。回归例覆盖前导空行、错误指纹和只收到部分候选。[表头初始化](../../sample/sample_teacher.py#L202) · [恢复入口](../../sample/sample_teacher.py#L548)
2. **报告“最多列 50 个问题”意外改变了评分。** 同一题的多个 rollout 如果带有互相矛盾的标准答案，应归入未决。审计先计算全部冲突题号，再给报告截取前 50 个；评分循环直接用这份短名单。临时构造 51 道选择题，每题两条回答、gold 分别为 A 和 B。实际评分识别出 51 道冲突，却得到 **2 条正确、100 条未决**，预期为 0 和 102。当前正式 24 个评测单元中，此类“同一行号的 rollout 间 gold 冲突”为 0；第 3 节说的是不同数据行之间的同题异标。修法是内部保留完整集合，仅在输出报告时截断示例；unsupported 题号也使用相同原则。[审计截断](../../evaluate/rescore.py#L75) · [名单参与评分](../../evaluate/rescore.py#L201)
3. **Warmup 交接对数据路径设了两套兼容规则。** 来源与目标共用训练文件路径时，函数在比较 batch size、seed、提示设置之前就返回成功；换了路径才比较这些字段。在内存中载入 naive 和 Actor 配方，把目标 batch 从 64 改为 32，函数仍返回 `same_data_path: true`。两份正式配方目前都是 64，此例验证的是该函数的盲区。建议先统一核对游标接续需要的设置，再根据路径决定是否要比较两份数据的有序内容。验收覆盖“同路径但 batch 不同”和“异路径但有序训练内容相同”。[交接兼容函数](../../gad/tools/pipeline.py#L1150)

## 8. 再审查：会影响哪项实验决定（2026-11-18）

现有 base-GAD 可以继续作 H200 的整套方法对照。长跑前优先处理 checkpoint 保留，用首批真实 Judge 返回检查各维度监督覆盖。naive 结束后、选 Actor 奖励参数之前核对影子日志覆盖。外评修订可直接用各模型同批原始回答离线复评。以下为审查发现，本轮只更新文档。

### 长跑前：自动清理可能选错要保留的断点

保留工具和训练恢复入口各自定义了“完整”。以本机 SeqKD 的真实单卡文件在临时目录模拟两个保存步，保留数设为 1。只让最新步缺少 Actor 的 `extra_state`，两处检查都返回成功，旧的完整步进入拟删除列表；同阶段 FSDP 恢复会打开缺少的文件，读取学习率调度器与随机数状态。再把最新步的优化器换成零字节文件，训练校验报错，保留计划仍拟删除旧步。复现只调用规划函数。带完整扩展清单的 rubric 断点还有额外的分片检查，风险示例来自普通保存路径。[保留计划](../../gad/tools/prune_checkpoints.py#L47) · [交接工具中的检查](../../gad/tools/prepare_gad_checkpoint.py#L104) · [训练检查](../../gad/tools/pipeline.py#L567) · [FSDP 恢复](../../gad/.backends_gad_extensions_v1_f0ce22a97d40/seqkd/verl/utils/checkpoint/fsdp_checkpoint_manager.py#L122)

建议让“可以据此删除上一个断点”和“可以同阶段恢复”共用判断，按阶段实际保存的角色、rank 和状态检查文件。最新步不满足时保留上一份完整点。首次跨阶段交接、只导出 HF 仍按各自实际需要的文件判断。这项修改可独立于损失、采样和评分协议。

### 训练：正确性标签补了什么，怎样检验

原 GAD 的 BT 损失要求同题 Teacher 得分高于 Student。我们重建训练时的 `pair_id`，用源 UID、实际分词、Teacher 在训练长度内可见的回答、Student 回答标识和出现步次核对配对，再用同一 scorer 重判 Teacher。本机 **9,293** 次“学生自然结束且已判对”的配对全部对上。Teacher 也被判对 **8,936** 次、明确判错 **172** 次、无明确答案 **181** 次、未决 **4** 次。172 次里有 **165 次双方都写完**，涉及 **114** 个不同源 UID，例如 step 281 的 `d9d4812a-93ca-4bae-9ee8-b24d8254f633`。这些是按学生已答对筛选后的训练样本出现次数。同一道题可能贡献多次，评分器本身也有误差。[BT 损失](../../gad/extensions/worker.py#L115) · [训练监控原始记录](/tmp/bloxopd_h200_runs/h200_baseline_06b_17k_n4/gad/extension_metrics.jsonl)

这给正确性辅助监督提供了具体理由。另一个同时存在的因素是能否在预算内写出答案。按本机基线回放，学生有效负标签共 59,755 条，其中 38,758 条来自截断回答（64.9%）。截断且确认答对的还有 88 条。监控只存标签和结束原因，不能把 38,758 条全部归为无答案。比较 naive 时，建议让两组 Critic 打同一批固定回答，分别报告“两条都答完且一对一错”的排序、优势差，以及“截断且给出答案”和“截断且无答案”的数量。后两项应保留 scorer 的解析状态。[标签映射](../../scoring/math.py#L1235) · [逐条监控](../../gad/extensions/actor_reward.py#L137)

**naive 的进度标签可以掩盖错误严重度标签长期缺失。** 用真实标注流程和模拟 Judge 连续走四步，每步入选的 21 个 Student 都有合法进度值，严重度全为 `null`。四步的空监督计数均为零，严重度的有效样本数和直接损失权重也都为零。当前日志已经逐维计数，并标注了只收到一个维度的情况。空监督告警按“任一过程维度有效”计算，另一处覆盖率告警以整个批次为分母，难以识别这个问题。建议用首批真实返回按 Teacher、Student 分开看入选且可标注回答中每个维度的有效比例，持续为零时提示。保留合法 `null`。naive 的 Actor 只用对抗分，后续若要把严重度也接入 Actor 奖励，先核对这个头收到了多少监督。[逐维计数](../../gad/extensions/online_v2.py#L62) · [覆盖率告警](../../gad/extensions/quality_monitor.py#L11)

**共同的 BT 项也有数值差异。** 单头基线在 BF16 logits 上做差并算 BT，四头 naive 先转 FP32。固定四对相同的 BF16 logits，把辅助损失设为零，两个实现的 BT 分别为 1.03125 和 1.03534，其中一个学生 logit 的梯度分别为 0.06226 和 0.06250。这个小例说明“只改变辅助监督”的消融还需对齐 BT 精度和 Critic microbatch；它没有估计二者对正式榜单的影响。[单头实现](../../gad/.backends_gad_extensions_v1_f0ce22a97d40/gad/verl/trainer/ppo/core_algos.py#L832) · [四头实现](../../gad/extensions/worker.py#L112)

**Actor 选参还应检查每步有多少题。** 影子日志读取器验证每个已有 UID 有四条回答，命令也检查 272–542 步都出现。临时输入每步只留一题四答，1,084 条仍能通过这两项日志检查；正式输入应为每步 64 题、256 条，合计 69,376 条。最终 checkpoint 完整也不能证明独立日志写齐。建议按冻结配方核对每步的 UID 数和行数，再划选择集和复核集。本机基线实查 17,344 组均有四个不同的回答 ID。[影子日志读取与选参](../../gad/tools/select_actor_reward.py#L25)

### Teacher 采样：指纹与实际执行要一致

- 默认离线 Teacher 是只支持 non-thinking 的 Qwen3-30B-A3B-Instruct-2507。采样探针却要求同一条提示在 thinking 开关翻转后必须变样，使用忽略这个开关的官方模板时会在加载引擎前报错。可切换模型适合保留开关对照，固定模式模型只需验证请求的模式受支持，并记录实际渲染。[默认配方](../../sample/configs/sample.yaml#L31) · [探针实现](../../sample/teacher_engines.py#L329) · [官方模型说明](https://huggingface.co/Qwen/Qwen3-30B-A3B-Instruct-2507#model-overview)
- 另一方向，额外的 `engine_kwargs` 可以覆盖真正交给 vLLM 的 model、tokenizer 或 dtype。用替身捕获真实构造路径的参数，改模型和 dtype 后采样指纹仍相同。若向同一索引续采，来源不同的回答可能被当作同一批。建议先合并最终参数，再从实际生效值计算指纹，或禁止重复声明模型身份字段。当前 H200 使用既有 Teacher 池，这个复现针对未来采样。[引擎构造](../../sample/teacher_engines.py#L275) · [指纹构造](../../sample/teacher_engines.py#L316)
- 上轮修正了采样器覆盖带前导空行索引的问题。下游还有两个读者：转换脚本直接读第一物理行，训练 runtime 对每一行直接解析 JSON。同一份“空行＋正式表头＋一条原记录”通过续采检查，训练初始化报 JSONDecodeError。当前正式 Teacher 索引空行数为零。可复用同一套跳空行、定位表头的读取逻辑。[转换脚本](../../sample/scripts/run_sample.sh#L307) · [训练读取](../../gad/extensions/runtime.py#L32)

### 可直接简化的重复工作

| 位置 | 实测与最小改法 |
|---|---|
| 四头 Critic 的辅助损失 | 本机 GAD 配方每个逻辑 minibatch 256 条，按 2 条分成 128 个 microbatch。Teacher 与 Student 各重算一次同一组三维损失权重，末尾监控再算一次。固定输入调用计数为 **257 次**，其中含张量有限性与非负检查。逻辑 minibatch 入口统一计算与验证一次，把系数传给损失及监控即可。端到端节时待测。[权重公式](../../rubric/core/losses.py#L12) · [训练循环](../../gad/extensions/worker.py#L109) |
| 无 replay 的 Critic 输入 | 正式 naive 关闭 replay，当前批的 Teacher、Student token 已在内存，rubric 路径仍从 Python 列表重建 8 个 Critic 输入张量。用正式宽度和 256 条合成回答在单线程 CPU 上调用一次，输出张量共 152 MiB，耗时约 1.35 秒。可让新批对象共享只读输入张量，另存标签，混入历史回答时仍需重建。更改前后应对齐有效 token、掩码、位置和一次参数更新。这个计时仅覆盖合成输入的打包。[分支入口](../../gad/extensions/runtime.py#L157) · [组批](../../gad/extensions/critic_batch.py#L60) |
| GAD 续训检查 | 只读调用本机已完成 run 的恢复决策，在一次调用里，同一批 19 个交接 HF 文件各哈希两遍，合计读取 5.08 GiB，其中不同文件共 2.54 GiB。当前调用内复用一次计算结果即可，下次恢复时重新核对。[恢复决策](../../gad/tools/pipeline.py#L741) |
| Judge 服务与缓存身份 | 在临时模型目录仅改权重文件修改时间，所有文件内容 SHA256 相同，服务指纹却改变。当前身份包含 inode、mtime 和 ctime，复制同一权重到新盘也可能使旧标签无法复用。可用文件属性加速本机哈希缓存，跨机器身份以实际权重、模板、模型配置与协议摘要为准。历史标签需保留原身份规则。[Judge 身份](../../gad/tools/extension_config.py#L334) |
