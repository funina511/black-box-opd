# GAD n=4 三组对照实施方案（baseline → naive rubric → actor-rubric）

状态：2026-11-05 起草，同日按评审意见修订（见文末修订记录）；2026-11-07 已完成代码、配置及第7节工程验证（三组各2+1步），见 [实施报告](../../reports/gad_n4_20261105/README.md)。本文只规定代码改动、配置、验证和运行顺序；三组正式训练均由用户启动，执行模型不得自行启动正式训练或正式评测。第3组正式参数仍待完整naive日志选参和用户确认。

## 1. 为什么改为 n=4

依据 [Rubric 两版设计与近两周实验汇报](../Rubric两版设计与近两周实验汇报_20261105.md) 和离线诊断 [pair_counterfactual.py](../../reports/rubric_actor_diag_20261105/pair_counterfactual.py)（输出见同目录 `pair_counterfactual.txt`），数据来源是 `runs/rubric_actor_06b_17k_v1/gad/extension_metrics.jsonl` 中 34,688 条学生回答的四头预测。

1. **n=2 时 Actor 只收到"两条谁更好"。**GRPO 组内标准化后，只要两条不平局且分差明显大于 ε（1e-6），优势就近似为 ±0.707，分差大小不起作用。上一轮 β=0.05 时 rubric 分差中位数约 0.018，对抗分差中位数 1.73。在 Actor-rubric 自己生成的回答上做反事实比较，加入 rubric 只改变了 55/17,344 对（0.32%）的排序。
2. **上一轮 −1.23pp 的原因尚不能确定。**rubric 对排序的直接干预很少，所以本次下降尚不能单独归因于 rubric 奖励，但结果值得重视。另外，两次 run 的回答、参数和训练轨迹会逐步分开，奖励精度也不同（BF16/FP32），不能当作同条件的重复实验，也不能用来估计训练噪声阈值。旧结果只作历史参考（八项平均相差约 1.2pp，MMLU-Pro-Math 相差约 4.7pp，开发集贪心正确率方向与测试集相反）。
3. **n=2 时可对比的组太少。**同题两条中一对一错的组只占 13.8%，两条都截断的组占 43.3%。按题目难度做 beta-binomial 拟合（能复现 n=2 实测比例）外推，n=4 时有对错对比的组约 25%，全截断组约 31%。这是模型假设下的外推估计（假设学生分布与上一轮相同），不作为验收预期，以第 5.5 节的实测组构成为准。
4. **rubric 信号本身弱。**两条都写完、一对一错（CW）时，答对那条排在前面的比例：对抗分 59.3%，ĉ 61.6%，ĉ+p̂−ê 60.7%。在 CW/CT 上，只用 ĉ 时翻转约 85% 朝答对方向，加入 p̂/ê 后约 64%。所以 Actor-rubric 的分量和权重要先在 n=4 数据上离线选定（第 6 节），不沿用 (1,1,1)、β=0.05。

## 2. 目标与边界

- 目标：在同一套 n=4 GAD 设置下比较三组，只改变各组本来的方法差异。
- 不重跑 SeqKD 和 Warmup。原因是本轮只改 GAD 设置，`rollout.n` 只作用于 GAD，与 `rollout.n_seqkd`、`rollout.n_warmup` 无关。说明现有实现：
  - SeqKD 的训练目标是 Teacher 回答的监督学习；训练循环里仍有学生生成调用（seqkd backend `ray_trainer.py` 第 1320–1327 行），但生成结果不进入 Actor 更新。`pipeline.py` 第 824 行注释"不生成学生回答"不准确，实施时可顺带更正注释，不改 SeqKD 行为。
  - Warmup 每题采 1 条学生回答（`rollout.n_warmup: 1`）用于训练 Critic；Actor 从第 10 步起按 Teacher 回答做监督学习。
- 旧 n=2 结果只作参考，不与 n=4 结果混在同一张对照表中下结论。
- 本轮不做：1.7B 学生（作为下一阶段新实验系列）、多 seed、Actor c-only 消融、新采 API 数据、Judge 协议修改、replay。

### 5.1 统一 FP32 奖励路径

- 新增开关（建议名 `rubric.actor_reward_fp32`；第 1 组 rubric 关闭，开关放在 rubric 之外的公共位置，命名由实现时决定，需在报告中写明）。开启后，对抗分在进入 GRPO 前转为 FP32。
- 三组全部开启，消除上一轮 BF16/FP32 的差异。
- 默认关闭，旧配置行为不变。

### 5.2 Actor-rubric：分别归一化后加权

对同一 uid 组内的 n 条回答：

```text
r_i      = w_c·ĉ_i + w_p·p̂_i − w_e·ê_i
z(x)_i   = (x_i − mean_g(x)) / (std_g(x) + ε)            # 与 GRPO 相同：无偏 std，ε=1e-6
zr_i     = (r_i − mean_g(r)) / max(std_g(r), τ)          # rubric 分母设下限 τ
s_i      = z(adv)_i + w · zr_i
A_i      = GRPO(s)_i                                      # 原 GRPO 再做一次组内标准化
```

- **计算位置：在 driver 上按完整 uid 组计算。**Critic worker 只返回每条回答的四头分数（FP32），不在 worker 内做组内运算。原因：Critic microbatch 为 2，且数据按数据并行切到不同卡上，同一 uid 的 4 条回答可能分散在不同 microbatch 和不同 worker 上。driver 汇总全部回答后按 uid 计算 `s_i`，作为 `token_level_scores` 放在最后一个有效 token 上，原 GRPO 不改。需确认 `use_kl_in_reward=False`，否则 KL 项会混进 `s`。
- **同一个函数：**训练、第 6 节离线选择和第 5.5 节监控重算，复用 `actor_reward.py` 中同一个组内奖励函数，避免三处公式不一致。
- **直通规则（逐组判断）：**rubric 在该组的有效贡献为零时，不做内层归一化，直接让该组的 FP32 对抗分进入原 GRPO。包括两种情况：
  - w=0（整个 batch 直通）；
  - w>0，但该组 `std_g(r)=0`（组内 rubric 分数完全相同）。
  
  原因是两次归一化在组内 adv 分差接近 ε 时与直接 GRPO 不等价（例：adv=[0, 1e-8, 2e-8, 3e-8]，直接 GRPO 首条优势 −0.0148，两次归一化为 −1.162）。
- **零方差的定义：**`std_g(r)=0` 时直接令 `zr=0`（并按上条直通），不先计算除法，避免 τ=0（含第 25 百分位数恰为 0、或 τ=0 敏感性设置）时出现 0/0。`std_g(adv)=0` 时 `z(adv)=0`，与 GRPO 一致。
- **τ 的作用和边界：**归一化解决尺度问题，但会把很小的 rubric 分差放大（例：r=[0.500, 0.501, 0.502, 0.503] 时，不设下限的 z(r) 为 [−1.16, −0.39, 0.39, 1.16]）。τ 只限制 rubric 在**混合前**相对于 `z(adv)` 的尺度，不代表置信度，也不保证最终优势变小。对抗分在组内无区分力（`std_g(adv)` 接近 0）时，外层 GRPO 会把混合后的微小 rubric 差异重新放大，rubric 仍可能主导该组的最终优势（例：adv=[1,1,1,1]，r=[0.500000, 0.500001, 0.500002, 0.500003]，w=1，τ=0.05 时，混合前 rubric 分量约 [−3e−5, −1e−5, 1e−5, 3e−5]，最终优势约 [−1.12, −0.37, 0.37, 1.12]）。这是允许的行为（对抗分无法区分时由 rubric 给方向），本轮不另加门控参数，只按第 5.5 节单独统计。τ 只作用于 rubric，对抗分保持原 GRPO 行为。τ 按第 6 节事先写定的规则确定。
- 外层 GRPO 再标准化后，Actor 优势的组内尺度保持标准化，与 baseline 同一量级；rubric 改变组内的相对顺序和间距。这不保证实际梯度范数或参数更新幅度与 baseline 相同，需在训练日志中对照 Actor 梯度范数。
- 新增 `rubric.reward_source: adv_plus_rubric_groupnorm`，新增系数 `rubric.actor_reward_group_weight`（w）和 `rubric.actor_reward_rubric_std_floor`（τ）。已有的 `adv_plus_rubric`（原始分数相加）保留不动。
- 说明：n=2 时外层标准化又会退化为只看顺序，所以本模式的意义依赖 n≥3。配置检查在 n=2 时给出警告，不报错。

### 5.5 组内诊断：复用现有配对统计，只补缺项

现有 `actor_reward.summarize`（`gad/extensions/actor_reward.py` 第 138–195 行）已经按组内全部配对统计（`combinations`，n=4 时每组 6 对），包括按 CW/CT/TW/TT/WW/CC 分类的顺序改变、`right_wrong_pairs`、`corrected`、`damaged`、TW 的 `toward_T`，并且只在两条正确性标签都已知时计入一对一错配对。这些统计保留不改，只补：

- **新奖励模式：**`summarize` 中的奖励重算改为调用第 5.2 节的同一个函数，使统计在 `adv_plus_rubric_groupnorm` 下正确。
- **组构成：**有对错对比的组、全截断组、全答对组、组内优势全为 0 的组各自的比例。
- **按类别统计平均优势：**C、W、T 三类回答在 `A_adv` 和最终 `A` 下的平均值。
- **组内 C−W 优势差：**只在同组内同时存在 C 和 W 的组上计算"组内 C 的平均优势 − 组内 W 的平均优势"，再按组平均；分别在 `A_adv` 和最终 `A` 下计算，报告两者之差。避免不同难度题目的类别构成影响指标。没有这类组时记为 N/A。
- **rubric 尺度：**组内 rubric 标准差的分布（分位数），以及顺序改变中来自 `std_g(r) < τ` 组的比例；直通组（`std_g(r)=0`）的数量。
- **对抗分无区分力的组：**`std_g(adv) < 1e-5`（仅用于统计，不是门控）的组数，以及这些组中 `|A − A_adv|` 的平均值。
- **Actor 梯度范数**与 baseline 对照（第 5.2 节）。
- 校准沿用现有指标（ĉ 对 scorer，p̂/ê 对 Judge 标签），第 2 组在影子模式下同样记录。
- 每步记录，并维护最近 10 步窗口（现有机制）。

## 6. 第 3 组的分量、权重与 τ 选择（在第 2 组日志上离线进行）

所有计算使用第 5.2 节的同一个函数，输入第 2 组影子日志中的四头预测和对抗分。

**数据划分：**按 `question_id` 的哈希把题目分成两半，同一道题跨步骤始终在同一半。一半为选择集，用于选参；另一半为复核集，只用于复核，不参与选择。

**候选：**

- 分量：完整 `(w_c,w_p,w_e)=(1,1,1)`，以及只用正确性 `(1,0,0)`。
- 组权重：`w ∈ {0.25, 0.5, 1, 2}`。
- τ：在看任何 w 的结果之前，按选择集上组内 rubric 标准差（对应分量各自计算）的第 25 百分位数确定，每种分量一个 τ。这是预先固定的工程规则，不是已验证的可靠性阈值。τ=0 和中位数两种设置只作敏感性参考，不参与选择。

**记号：**一对一错配对指两条回答的 scorer 正确性标签都已知、一条为 1 一条为 0 的配对（标签未知的排除；截断回答按 scorer 实际标签计，不默认视为错误）。修正 = 原按对抗分把错的排前、改后把对的排前；破坏 = 反之；净修正 = 修正 − 破坏。C−W 优势差的变化按第 5.5 节的组内定义计算。

**约束（事先写定，全部基于选择集）：**

1. 一对一错配对中，修正 /（修正 + 破坏）≥ 80%。修正 + 破坏 = 0 时比例记为 N/A，视为不违反该约束（没有改变排序就没有方向错误），不记作 0% 或 100%。
2. 只看两条都写完的一对一错配对（CW），净修正 ≥ 0。目的是避免结果主要来自"识别截断"。
3. 改变顺序的 TW 配对中，朝 T 的比例不超过 50%（长度偏好的观察约束，不是数学正确性的充分判据）。TW 没有顺序改变时记为 N/A，视为不违反。
4. 对抗分不相等的配对中，按 `s` 排序后顺序改变的比例不超过 25%，用于限制排序干预的范围。低改变率不能保证更新力度仍主要由对抗分决定。顺序改变率不设下限，作为干预强度指标报告。
5. 强度要求：净修正 ≥ 0，且组内 C−W 优势差相对 `A_adv` 增加（> 0）。

**选择规则：**

- 在满足全部约束的候选中，依次按以下顺序比较：净修正更大者优先；再按组内 C−W 优势差的增加量更大者优先；仍并列时取 w 较小者。两种分量一起比较。
- 净修正为 0 但 C−W 优势差增加的候选保留，单独标注为"主要改变更新力度，不改变排序"。
- 复核：在复核集和后期窗口（step 450–542）上分别重算约束 1–5。任一约束不满足时如实报告，由用户决定。
- 报告内容：全部候选在选择集和复核集上的约束值（N/A 照实标出）、净修正、组内 C−W 优势差变化、顺序改变率（CW 和 CT 分开）、对抗分无区分力组的数量和优势变化，以及 τ 的敏感性参考。由用户确认后冻结。
- 都不满足时，如实报告，由用户决定是否继续第 3 组。不为满足条件扩大网格或改标准。

离线结果反映的是第 2 组的 Critic 轨迹，第 3 组的 Critic 会继续变化，因此第 5.5 节的在线诊断需要持续对照这些约束。

## 9. 风险

- **耗时：**三组依次运行，学生回答数和 Judge 名额都翻倍，单组会明显长于 n=2 的约 51 小时。以短测实测为准，必要时由用户决定是否调整。
- **组内诊断的分母：**n=4 时可对比的配对多了，一对一错的配对数量会上升，但仍集中在较易的题上。
- **影子日志体积：**每步 256 条，比上一轮大一倍，需确认 `extension_metrics.jsonl` 的体积可接受，必要时拆分为单独文件。
- **τ 的选取依赖第 2 组的 Critic 轨迹：**第 3 组的 rubric 尺度可能漂移，在线监控"顺序改变中来自 `std_g(r) < τ` 组的比例"。
- **第 3 组的离线选择可能无解：**按第 6 节如实报告，不强行启动。
