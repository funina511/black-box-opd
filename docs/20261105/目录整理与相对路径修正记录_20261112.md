## 2. 相对路径修改

五份 `configs/launch_*.yaml` 的项目内路径从旧绝对路径改为相对于 YAML 所在目录的路径。例如：

```yaml
models.student: ../assets/models/Qwen3-0.6B
data.train_file: ../data/dapo_math_17k_gad_v2/gad_train.parquet
scoring.math.entrypoint: ../scoring/math.py
validation.scorer_path: ../scoring/math.py
backends.source_repo: ../gad/verl
run.output_root: ../runs
run.python_bin: null
budget.init_from_warmup_run: ../runs/rubric_direct_06b_17k_20261026
```

同样处理了模型初始化、Teacher索引、数据manifest、quick-dev、评测资产、rubric spec/prompt、Judge模型路径。两个采样配置注释中的旧机器路径也已改为通用示例；实际采样设置未变。

路径规则：

- YAML 中的路径以该 YAML 所在目录为基准；根 `train.yaml` 与 `configs/` 下 YAML 的相对层级不同。
- 命令行覆盖中的路径沿现有调用目录规则处理。
- `budget.init_from_warmup_run` 显式路径采用上述规则；只有 run 名称或历史别名时，保留原 run 查找逻辑。
- `run.python_bin: null` 使用启动 pipeline 的解释器；先激活目标环境，再设置 `GAD_PYTHON="$(command -v python)"`。
- 启动后保存的 resolved config 仍记录实际绝对路径。这是实验身份和恢复依据，不应为了迁移批量改写旧 runs。

训练加载器做了两处小修正：

1. 完整 YAML 的 scorer 冲突校验使用已经解析的相对路径；未显式指定 validation scorer 时仍沿用统一 scorer 默认值。
2. 显式 Warmup 来源路径加入统一解析，保留裸 run 名称/别名行为。

没有修改训练 loss、奖励、Judge协议、过程抽样、replay、阶段交接或模型初始化逻辑。

## 3. 刻意保留的内容

- **`judge_fix/`**：旧 `rubric_direct_06b_17k_20261026` 的冻结配置仍引用里面的 backend、spec、prompt 和 scorer。当前新运行使用正式目录，但未来读取旧来源/复现实验仍可能需要原路径。本机暂不移动，迁移版不带。
- **`gad/verl/` 和活动 backend**：现有运行、Git worktree和测试仍使用。新机可以从 bundle 重建，不代表运行中的源机可以直接删除。
- **旧离线 rubric 工具及其测试**：`rubric/tests/` 仍导入根目录下的 model、losses、train_offline 等模块。先明确入口归属，暂不连带重构测试体系。
- **旧过程协议模块**：direct 路径仍涉及部分导入和身份哈希；直接删文件会改变协议身份或破坏导入。本轮不动。
- **`gad/deepscaler/` 和原安装文件**：固定 backend 中仍存在对 deepscaler 的导入，不能仅因当前主流程没调用就判为完全无用。
- **replay 实现**：按用户要求保留，即使当前配置关闭。

因此本轮完成的是明确无运行依赖的目录减法，以及配置可移植化；没有宣称所有历史目录都已清除。
