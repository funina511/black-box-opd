# 训练验证提速与目录整理计划

日期：2026-09-24。状态：目录迁移及代码改造已实施；GPU 恢复训练与实测提速待验证。

## 1. 目标与边界

1. 降低 SeqKD → Warmup → GAD 训练期间验证的时间占比。
2. 在 LMOps 下集中管理本实验的配置、启动入口、专用数据、checkpoint、日志和报告。
3. 保留当前训练进度、教师索引、训练/验证划分，以及原版核心损失和更新顺序。
4. SeqKD 保持独立基线；Warmup 从初始学生开始；GAD 接续 Warmup。
5. 目录迁移不同时改变训练数据选择策略、训练 batch、学习率或训练步数。当前 select=all 是独立的实验选择，不在这次迁移中自动改为过滤集。
6. 共享模型、原始数据和 Conda 环境暂不搬运，在 LMOps 提供统一的链接或配置入口。只整理本实验相关内容，不移动 RLRM/runs 下其他项目。

- 主配置：RLRM/runs/configs/run_qwen3_1.7b.yaml、sample_qwen3_1.7b.yaml。
- 训练输出：RLRM/runs/gad_qwen3_1.7b/qwen3-1.7b-4x3090。

- 当前普通训练步约 31 秒；每 50 步验证 512 题，一次约 105–116 分钟，已记录耗时约 80% 用于验证。
- 最近一次完整验证平均回答约 5686 tokens，约 57% 达到 8192-token 上限。直接缩短生成上限会改变指标含义。
- 成功运行额外使用 models.param_offload=true、optim.actor_ppo_max_token_len_per_gpu=10240；源 YAML 仍写 false 和 12288。
- SeqKD 支持从本阶段 checkpoint 恢复模型、优化器及 dataloader；GAD 有独立的 --resume-gad 路径。
- 验证在 checkpoint 保存之前执行，因此不能把“进入第 600 步验证”等同于“第 600 步已经保存”。

## 5. 第一阶段：低风险验证提速与配置统一

### 配置调整

- resources.test_freq：50 → 200。
- resources.save_freq：保持 50。
- data.val_batch_size：16 → 64，先验证一轮显存与耗时，再决定是否保留。
- rollout.val_n=1、val_do_sample=false、8192-token 上限保持不变。
- 当前续跑取消重复初始验证：run.val_before_train=false。新实验仍应保存一份初始基线，不能把续跑选项误当成不需要基线。
- 将成功运行的 param_offload=true 和 actor token 预算 10240 写入实际实验配置，避免每次靠临时 --set 才能运行。

频率调整约减少 75% 常规验证次数，最终步骤仍需全量验证。val_batch_size 调整只减少外层调用与同步开销，不承诺线性加速。保持回答长度，确保前后数学准确率可比较。

### 配置与入口

- 顶层脚本从自身路径定位 LMOps，不依赖启动时的工作目录。
- 训练和采样统一采用“相对 YAML 所在目录解析路径”的规则；训练现有解析器可复用，采样侧需要补齐，不能假定现有 shell 已支持。
- 模型、数据、日志和输出路径解析后写入 resolved_config；不依赖未经实现的 YAML 环境变量展开。
- 顶层脚本只转发现有参数，不复制阶段调度逻辑；支持任意目录调用、dry-run 和恢复参数。
- 预检、Hydra 输出和启动日志均显式指定去向，停止在工作目录下随机产生新 outputs。
- 更新 Git 忽略规则：跟踪代码、配置和文档，忽略数据、权重、checkpoint、日志、缓存及本机资源链接。

## 6. 第二阶段：过程子集与阶段末全量验证

第一阶段稳定后增加可选模式，默认方案为：固定 128 题每 200 步监控，阶段结束验证全部 512 题。

### 实现方案

- 增加 validation.quick_size=128、quick_seed=42、final_full=true 等明确配置项。
- 从已有 dev 集选择固定 UID 子集，保存父 dev 文件哈希、UID 列表和选择方法；三个阶段复用同一子集。
- 保留原完整 dev 文件，创建独立 quick_dev.parquet，避免覆盖训练正在读取的数据。
- 训练器持有 quick/full 两套验证 dataloader；中间步骤用 quick，最后一步只用 full，避免重复验证。
- 输出记录带 validation_scope=quick/full、样本数、子集哈希、回答上限及耗时。过程子集与全量准确率使用可区分的日志键，不能拼成同一条未标注曲线。
- 验证时间拆成生成、解码、ROUGE-L、数学评分及总耗时；目前日志只提供总 testing 时间，尚不能精确拆分各部分瓶颈。
- 保留原 ROUGE-L 诊断；如计时确认它占比显著，再单独增加关闭过程 ROUGE 的选项，阶段末保留原诊断。
- 完成判定验证最后的 full 记录与最终 global step 对应；不能凭历史某条 quick 记录标记阶段完成。
- 完整 dev 评估与 AIME/MATH500 等独立 benchmark 分开记录，不能将过程子集结果称为最终测试成绩。

按现有耗时线性估算，128 题约 26–29 分钟/次；实际受长度分布、KV 调度和评分开销影响，实施后测量。第一阶段可独立完成，不必等待此阶段开发。

## 7. 当前任务的安全衔接

1. 实施前确认当前进程、正在验证的步骤与最新完整 checkpoint；记录 actor/optimizer/extra_state/data.pt 和 latest marker。
2. 当前任务运行时仅提供 LMOps 内的导航/链接入口，不移动其正在写入的实体目录，也不修改其 backend 文件。
3. 将配置整理和验证设置变更单独记录，准备好恢复命令与回退映射。
4. 等 checkpoint 完整落盘，并在任务安全退出后迁移实体；同一文件系统优先原子改名，跨文件系统采用复制、校验、切换。原输出保持可恢复。
5. 迁移后保留旧路径 → 新实体的兼容链接，避免模型元数据、历史脚本和 dataloader 序列化状态中的旧路径失效。
6. 不并发启动两份相同 run_id 的训练。先只恢复 SeqKD，确认从正确 global step 继续、执行真实 actor 更新且能写入下一 checkpoint，再衔接后续阶段。
7. 修改验证频率或目录不能让已完成阶段重新训练。现有完成签名包含全部配置与路径，需区分训练设置变化、验证设置变化和纯路径迁移：训练内容哈希不变的迁移不当成新训练；验证变更必要时只补评估。保留审计记录。
8. 不直接覆盖历史 resolved_config：保存原快照，新启动写新的解析配置与变更记录，根入口明确指向当前版本。

这是一份实施计划；当前训练的暂停、迁移和重启不在编写计划时执行。

## 8. 与本次整理分开的算法边界

- 微批上限补丁已增加逐分区检查；对单条样本仍可能超总预算的情形保持显式报告。
- 默认微批分组改变会影响不等长回答的梯度权重，现有文档和测试已说明；不再宣称与 pinned 逐位等价。
- 当前 n_warmup=1 相对仓库原始训练脚本 n=8 改变判别器见到的候选数。actor 去重不代表判别器也丢弃其余候选。
- 本轮目录与验证优化不暗中调整 n_warmup；修正文档的“无损”说法，并把采用 n=1 的调优设置与严格原版 n=8 的口径明确区分，后续决定以哪个实验协议为准。

## 10. 验收与交付顺序

A. 目录与配置：从任意工作目录执行顶层脚本 dry-run，解析到同一模型、数据和后端；LMOps/README 能定位所有实验文件；旧路径兼容链接可用。

B. 迁移完整性：数据行数/哈希、checkpoint 文件清单、latest step、教师指纹和 manifest 引用一致；历史记录保留。

C. 训练恢复：恢复已有 SeqKD checkpoint，不回到 step 0、不重复已完成阶段、不改变 dataloader 训练数据；能够完成真实 actor 更新和一次保存。

D. 验证：第一阶段确认每 200 步与最后一步验证，保存仍每 50 步；第二阶段确认固定 128 题过程验证、最后 512 题全量、指标分开、最终完成标记有对应全量记录。

E. 性能：报告调优前后每次验证耗时及总训练占比，不将预估速度写成实测结果；若 val_batch_size=64 显存不稳定，独立退回 16，不撤销验证频率调整。

实施顺序：配置与入口统一 → 第一阶段验证参数 → 安全迁移与恢复验证 → 第二阶段 quick/full 调度 → 文档与最终验收。
