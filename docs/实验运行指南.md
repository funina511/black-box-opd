# 实验运行指南

## 新建实验

日常维护根目录 `train.yaml`。`selection` 选择默认模型与数据，`catalog` 登记路径；公共训练字段设置学习率、生成、GPU、预算和保存规则。数据映射同时选择 train/dev/quick dev、manifest、teacher index 和教师指纹。

`scripts/train.sh` 顶部的 MODEL/DATASET 留空时继承全局选择；可填写它们，以及 NAME/STAGES/OVERRIDES。命令行参数最后生效：

```bash
cd /mnt/jinbo/RLRM/LMOps
bash scripts/train.sh --model qwen3_0.6b --dataset dapo_math_17k --name n2 --dry-run
bash scripts/train.sh --model qwen3_0.6b --dataset dapo_math_17k --name n2
bash scripts/train.sh --model qwen3_1.7b --dataset dapo_math_5k --name trial --set rollout.n=4 --dry-run
```

新实验的目录名为 `<模型>_<数据>_<备注>_<时间>`，实际路径在启动日志中打印。正式启动保存完整、路径已解析的 `runs/<运行名>/train.yaml`，并执行预检；`--dry-run` 只打印计划，不创建 run/guard、不使用 GPU。

覆盖顺序为公共默认值→模型/数据映射→可选覆盖文件→命令行 `--set`。多个 `--overrides` 文件按顺序加载。例：

```yaml
# 本次少量设置，可选，不必创建完整 train.yaml
rollout:
  n: 4
budget:
  stage_epochs:
    gad: 3
```

```bash
bash scripts/train.sh --overrides /path/to/trial.yaml --set rollout.n=2 --dry-run
```

每个 YAML 的路径先按自身目录解析；命令行路径按调用目录解析。新实验不覆盖已有目录。`--run-id NAME` 可显式指定新目录名，若已存在会报错。

## 训练预算

| 数据集（batch=64） | 每 epoch 步数 | 默认 SeqKD | 默认 Warmup | 默认 GAD |
| --- | ---: | ---: | ---: | --- |
| 5k：5000 条 | 78 | 156 | 78 | 78→156，新增 78 |
| 完整 17k：17405 条 | 271 | 542 | 271 | 271→542，新增 271 |

GAD 的 `budget.stage_epochs.gad=2` 是绝对目标，含 Warmup 的 1 epoch；希望 GAD 自身新增 2 epoch，设为 3。明确设置 epoch 预算时，固定 `*_steps` 不决定时长。SeqKD 是独立基线，Warmup 从初始学生开始，GAD 接续 Warmup。

选择另一个模型沿用同一份公共训练设置。复现其他预算或采样数量时，显式修改全局字段或本次覆盖参数，并检查 dry-run。

## 恢复已有实验

```bash
bash scripts/train.sh --run runs/<运行名> --resume --dry-run
bash scripts/train.sh --run runs/<运行名> --resume
# 临时更换同样数量的 GPU，保留训练设置
bash scripts/train.sh --run runs/<运行名> --resume --set resources.gpus=0,1,2,3 --dry-run
```

恢复使用已保存配置，全局默认值的后续修改不会改变这个实验。允许临时覆盖 GPU、解释器、日志、初始验证及保存/验证频率、保留次数，并记录启动参数；模型、数据、学习率、rollout 和训练预算的更改需要新建实验。GPU 数量仍以保存配置中的 `n_gpus_per_node` 为准。

已完成的阶段按签名跳过；已有 GAD checkpoint 使用 full-state resume。新 run 不需要 `--resume`；`--stages all` 与默认三阶段等价。

三个历史实验也可通过别名选择：

| 别名 | 原 run 目录 |
| --- | --- |
| `qwen3_0.6b_5k` | `runs/gad_qwen3_0.6b_5k/qwen3-0.6b-5k-seed42-n2` |
| `qwen3_0.6b_17k` | `runs/gad_qwen3_0.6b_17k/qwen3-0.6b-17k-n2` |
| `qwen3_1.7b` | `runs/gad_qwen3_1.7b/qwen3-1.7b-4x3090` |

历史 1.7B 是不同阶段参数和步数不一致的探索记录；其保存配置包含已核实的阶段覆盖设置，不应作为同等预算的 SeqKD/GAD 正式对照。GAD step 542 没有完成标记，评测时显式选择该步。

旧 `--model-name ... --experiment-name ...` / `--experiment ...` 选择已登记的历史 run，训练时按已有实验恢复；新实验推荐使用 `--model`、`--dataset`、`--name`。旧的显式 `--config .../experiments/<名称>/train.yaml` 通过兼容解析定位保存配置；恢复时加 `--resume`。普通独立 `--config` YAML 仍可供底层工具使用。

## 预检、评测和导出

```bash
bash scripts/preflight.sh --model qwen3_0.6b --dataset dapo_math_17k --skip-packages
bash scripts/preflight.sh --run qwen3_0.6b_17k --skip-packages
bash evaluate/run_eval.sh --run qwen3_0.6b_17k --dry-run
bash evaluate/run_eval.sh --run qwen3_0.6b_17k
bash evaluate/run_eval.sh --run qwen3_0.6b_17k --summary
bash scripts/export_model.sh --run qwen3_0.6b_17k --stage gad --step latest --dry-run
```

`--skip-packages` 是快速配置/数据/模型/后端检查，完整预检去掉它。新实验的独立预检报告默认在 `runs/_preflight/`；已有 run 的报告在其 `reports/`；`--report` 可以指定路径。

评测模型、数据和采样参数集中在 `evaluate/run_eval.sh` 顶部设置，详见 [评测说明](../evaluate/README.md)。训练的 non-thinking 和模型/数据/步数从目标 run 读取，准备好 checkpoint 后自动按需导出 HF 权重。

## 保存和目录管理

每 50 个 global step 及阶段末保存；每阶段轮换最近 5 次完整保存。清理监控每 30 秒检查一次，阶段结束再次检查。正在写入的 checkpoint、交接、已导出的模型和完成结果受保护，所以实际目录数可能超过 5。再次运行入口并跳过已完成阶段时不会清理旧结果。

仅预览手动清理：

```bash
/mnt/jinbo/miniconda3/envs/gad/bin/python gad/tools/prune_checkpoints.py --run qwen3_0.6b_17k
```

确认预览后可加 `--apply`；同一 run 正在训练或评测时拒绝手动清理。配置迁移未清理实际实验 checkpoint。

共享采样配置在 `sample/configs/sample.yaml`，继续通过 `scripts/sample.sh` 运行。性能候选在 `gad/configs/benchmark_candidates.yaml`，`scripts/benchmark_train.sh --run <历史 run> --candidate baseline` 默认只在临时目录做 Hydra composition；加 `--execute` 才会运行 GPU 短跑。

原实验配置/README/性能说明完整归档到各 run 的 `reports/legacy_experiment/`；原有 `RLRM/runs/configs/` 的训练与采样软链接已更新到保存配置/共享采样配置；`reports/config_migration.json` 记录源快照、文件哈希和阶段依据。全局模板进入 Git；运行配置与结果随整个 run 备份。
